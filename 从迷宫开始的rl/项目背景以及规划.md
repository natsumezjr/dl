# 项目长期规划：从迷宫强化学习到二进制漏洞挖掘

项目代码地址：

```text
https://github.com/natsumezjr/dl
```

## 1. 项目定位

本项目的长期目标不是停留在二维迷宫，而是通过迷宫这一可控环境逐步学习强化学习、奖励建模、规划模型、探索策略与复杂状态空间建模方法，最终将这些方法迁移到二进制漏洞挖掘任务中。

迷宫在本项目中不是玩具问题，而是一个工程化训练场。它具备以下优点：

1. 状态空间简单，可视化强；
2. 最优解可由 BFS 精确生成；
3. 可以清楚区分成功、失败、撞墙、绕路、重复访问、死胡同、探索不足等行为；
4. 可以逐步从确定性环境扩展到概率环境；
5. 可以模拟二进制漏洞挖掘中的路径搜索、状态爆炸、局部最优、无效路径、探索收益与稀疏奖励问题。

因此，本项目的基本路线是：

```text
简单确定性迷宫
→ 复杂结构迷宫
→ 局部可观测迷宫
→ 概率转移迷宫
→ 可探索任务
→ 类程序路径搜索环境
→ 二进制漏洞挖掘建模
```

---

## 2. 总体技术路线

项目分为三个近期阶段。

### 阶段一：1.x.y —— 模型是否具备 BFS 拟合能力

1.x.y 阶段暂时不研究 DQN，不研究 reward model，不研究探索策略。

它只回答一个基础问题：

```text
给定迷宫、当前位置和目标点，模型能不能学会 BFS 最短路径的本质？
```

这一阶段的任务可以是分类，也可以是回归。

可选任务包括：

```text
1. 输入 maze / agent / goal，分类预测 BFS 最优动作；
2. 输入 maze / goal，回归整张 BFS distance map；
3. 输入 transition，预测 delta BFS distance；
4. 同时预测 action policy 和 value / distance；
5. 用模型 rollout，检查是否能真正走到终点。
```

1.x.y 的目标不是训练强化学习智能体，而是评估模型结构是否有规划能力。

预期验收指标：

```text
success rate >= 95%
shortest-path success rate >= 80%
hard maze success 稳定
BFS gap 较小
泛化到随机 start / goal
泛化到不同 obstacle density
```

版本组织原则：

```text
每一个 x 对应一种模型结构；
每一个 y 只做参数调整、loss 调整、输入通道调整或数据规模调整。
```

建议路线：

```text
1.0.y  CNN action classifier
1.1.y  CNN + BFS distance / delta regression
1.2.y  U-Net distance field predictor
1.3.y  ResNet policy-value model
1.4.y  Value Iteration Network / differentiable planner
1.5.y  GNN message-passing BFS model
1.6.y  Transformer / attention planner
1.7.y  Hybrid CNN + graph / planner model
```

这一阶段结束后，选择最能拟合 BFS 的模型，作为后续 RM 与 Q model 的候选骨干网络。

---

### 阶段二：2.0.10 —— 替换 RM / Q model 骨干

2.0.n 阶段已经证明，普通 CNN/QCNN 对局部 reward 语义有一定拟合能力，但缺乏真正的全局规划能力。2.0.10 的目标不是继续改 reward 数据，而是把 1.x.y 中验证过的优秀 BFS 模型结构接入 2.0 系统。

2.0.10 的目标：

```text
1. 保留 v2.0.9 的 RM 数据工程、trajectory / local pair、debug probe；
2. 用 1.x.y 中最优秀的模型替换 RM backbone；
3. 用同类模型替换 Q model backbone；
4. 检查 RM 是否能更稳定地给出局部 reward；
5. 检查 Q model 是否能把局部 reward 转化成接近 BFS 的策略。
```

验收指标：

```text
RM:
  toward > away > wall
  stuck_escape > stuck_loop
  visit 不再成为错误的一阶目标
  primitive reward 分布不过度饱和

Q model:
  success rate 提升
  shortest path success 提升
  hard maze 不崩
  BFS gap 降低
  pure argmax 与 BFS tie-break 差距缩小
```

2.0.10 是一个承上启下版本：它不急着增加环境复杂度，而是验证“正确的模型结构”是否能接住 v2.0.9 已经整理好的 reward learning 体系。

---

### 阶段三：2.1.x / 2.2.x —— 迷宫复杂化与概率化

2.1.x 开始逐步复杂化迷宫，但不急于加入 demo，也不急于堆功能。每个版本只学习一种新方法。

建议路线：

```text
2.1.0  随机 start / goal + BFS 难度控制
2.1.1  多 profile maze generation
2.1.2  局部可观测迷宫
2.1.3  动态障碍 / 概率墙
2.1.4  key-door / hidden goal / exploration task
2.1.5  多目标与收益-风险权衡
```

2.2.x 可以进一步接近真实漏洞挖掘中的探索问题：

```text
1. 状态不完全可见；
2. 动作结果具有不确定性；
3. 部分路径短期无收益但长期有价值；
4. 一些路径会导致不可恢复失败；
5. 一些路径会打开新区域；
6. 探索覆盖率本身成为目标；
7. agent 需要在 exploitation 与 exploration 之间权衡。
```

这时，迷宫中的概念可以逐步映射到二进制漏洞挖掘：

```text
maze cell              → 程序状态 / basic block / symbolic state
wall                   → 不可行路径 / crash / invalid input
goal                   → 漏洞触发点 / crash target / sanitizer target
visited                → 已探索状态 / 路径重复
stuck loop             → fuzzer 卡在局部路径簇
explore timeout        → 有探索但未触发目标
wall recovery          → 错误输入后仍恢复到有效搜索
probabilistic transition → 输入变异产生的不确定路径效果
coverage reward        → 新路径覆盖率 / 新 basic block 发现
```

## 3. 项目近期执行顺序

近期不建议同时推进太多方向。建议顺序如下：

```text
1. 冻结 v2.0.9 作为 RM 工程总结版本；
2. 开始 1.0.0，做 CNN BFS action classifier；
3. 做 1.1.0，测试 distance / delta regression；
4. 做 1.2.0，测试 U-Net distance field；
5. 做 1.3.0，测试 ResNet policy-value；
6. 做 1.4.0，测试 VIN / differentiable planning；
7. 做 1.5.0，测试 GNN BFS；
8. 做 1.6.0，测试 Transformer planner；
9. 选择最优秀模型进入 2.0.10；
10. 在 2.0.10 验收 RM 和 Q model；
11. 再进入 2.1.x 其它稀疏奖励等问题的优化方向，逐步进入复杂迷宫。
12. 最后进入概率化、探索化环境，为二进制漏洞挖掘建模做准备。
```

## 4. 项目的核心原则

本项目不追求一次性做出复杂智能体，而是追求每一步都能解释失败原因。
不是追求完成任务，而是学会问题的本质归纳能力。
因此不倾向于打补丁式的补救，比如计算出BFS的最短路径直接送给模型，这没有任何意义。

核心原则：

```text
先定义目标，再设计数据；
先验证模型能力，再训练强化学习；
先看 debug 证据，再调参数；
先解决确定性环境，再引入概率性；
先在迷宫中学会方法，再迁移到二进制漏洞挖掘。
```

最终目标不是“让迷宫跑通”，而是建立一套可以迁移的强化学习工程方法：

```text
目标定义
数据构造
奖励建模
策略学习
调试诊断
模型选择
环境复杂化
概率探索
漏洞挖掘迁移
```
